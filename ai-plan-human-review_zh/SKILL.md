# AI 出方案，你来审

## 概述

AI 提案，人审批，AI 执行。编码任务中，AI 负责扫描项目上下文、评估问题，交付一份具体到文件和位置的改动清单——不再问"你来写还是我来写"。清单就是给你 Review 的交付物：你回"继续"之前不动任何文件；执行完汇报实际改动和验证结果，供你判断 AI 的修改是否合理。

## 触发条件

**激活：** 请求编写/生成/修改/重构代码；已给出改动清单后用户说"继续"；要求判断 AI 的改动是否合理。

**不激活：** 纯问答、代码解释、调试排错、审查人类写的代码、配置文件/文档、仅改名不改逻辑。

## 核心工作流

```
用户提交编码任务
       |
       v
扫描项目上下文（相关文件、功能角色、依赖与数据流）
       |
       v
+-- 评估与方案（不变）-----------------------------------+
| 1. 问题拆解        2. 难度(*~*****)                     |
| 3. 重复度(体力/有挑战)                                  |
| 4. 领域(舒适区/陌生)                                    |
| 5. 安全风险(无/注意/高)                                 |
| 6. 2-3 种方案      7. 关键代码片段(<=10行)              |
+---------------------------------------------------------+
       |
       v
+-- 改动清单 ---------------------------------------------+
| 改什么：行为层面的变化，逐条编号                          |
| 涉及文件：N 个（新增 x / 修改 y / 删除 z）                |
| 每个文件：                                               |
|   - 路径（新增/修改/删除）                                |
|   - 改哪里：函数/类/行号/配置项                           |
|   - 为什么改：对应哪条需求、方案或风险                     |
+---------------------------------------------------------+
       |
       v
一句话收尾："Review 完回「继续」，我再开始改文件。"
       |
       v
用户 Review -> 回"继续" -> AI 执行改动 -> 汇报实际改动 + 验证结果
```

评估必须在改动清单之前完成，两者都不能跳过。

## 分析维度说明

| 评估项 | 判断标准 |
|--------|----------|
| 难度 | 技术复杂度：读CSV=* / 状态机=**** |
| 重复度 | 纯体力（批量替换）vs 有挑战（设计算法） |
| 领域 | 根据你的工程背景判断：熟悉 vs 陌生（标注为学习机会） |
| 安全风险 | 无风险 / 需注意 / 高风险（见下方安全判定） |

## 安全风险判定

AI 根据项目上下文和任务内容判定，高风险或需注意时**必须给出具体提醒**，不可仅标注等级。

| 等级 | 场景（关键词） |
|------|--------------|
| **高风险** | SQL拼接、密码/密钥/Token处理、反序列化用户输入、文件上传/路径遍历、权限校验 |
| **需注意** | 数据库查询(SQL注入)、Cookie/Session、API脱敏、日志含敏感信息 |
| **无风险** | 纯计算、格式转换、无IO的工具函数、不含密钥的配置读写 |

## 项目上下文感知

分析前先了解项目。用 Glob/Grep/Read 浏览相关文件，识别框架和库（检查依赖文件），找到类似实现做参考。根据发现调整分析：

- 已有类似模块 → 方案遵循既有模式
- 涉及数据库/PII → 安全风险自动提升
- 跨多模块改动 → 提示影响范围
- 使用特定框架 → 方案遵循框架最佳实践

## 改动清单规范

清单是用户批准或驳回的对象，必须具体。

| 部分 | 要求 |
|------|------|
| 改什么 | 行为层面：哪里会变得不一样，逐条编号 |
| 涉及文件 | 准确数量，逐个标新增/修改/删除；超过 5 个按模块分组 |
| 改哪里 | 文件路径 + 函数/类/行号/配置项 |
| 为什么改 | 这个文件对应哪条需求、方案或风险 |

- 每一条都能落到"一个文件 + 一个理由"；"改一下相关模块"不算清单
- 位置暂时定不了时，说明原因并列出候选位置
- 执行时清单之外不做任何改动

## Review 关卡

- 清单只展示一次，结尾只留一句话："Review 完回「继续」，我再开始改文件。"（用用户的语言，保持一句）
- 不弹选择/确认框，不追问"要不要开始"，不问"你来写还是我来写"
- 只有存在待确认的清单时，"继续"才等于授权；在此之前不碰任何文件
- 用户提出修改 → 更新清单，再次等"继续"
- 执行中发现与清单不一致（多改/少改/新风险）→ 停下说明，等新的授权
- 用户明确说"不用 review，直接改" → 简短提醒一次，确认后直接改，改完仍补上实际改动清单

## 执行与汇报

- 只改清单内的内容，不夹带清理和重构
- 改完汇报：实际动了哪些文件、与清单的差异、验证结果（测试/构建/lint 跑了什么、结果如何）
- 没跑验证或验证失败要如实说明

## 审查 AI 的改动

用户说"看看这改动合不合理"/"review 一下这次 diff"/"AI 改得对不对"时：

- 先给结论：合理 / 有问题 / 有风险
- 再逐条列：文件:行号 + 问题是什么 + 为什么 + <=3 行修改建议
- 不整段重写，不擅自改文件
- 没问题就明说，不凑数
- 需要修的话，重新走改动清单流程（先出清单，再等"继续"）

## 红线清单

| # | 红线 |
|---|------|
| 1 | 未经评估 + 改动清单就直接改代码 |
| 2 | 未收到"继续"就动文件 |
| 3 | 改动清单缺少文件/位置/理由中任意一项 |
| 4 | 弹选择/确认框，或问"你来写还是我来写" |
| 5 | 夹带清单外的改动 |
| 6 | 改完只说"已完成"，不报实际改动和验证结果 |
| 7 | 审查 AI 改动时直接重写代码或擅自修改文件 |

**用户要求跳过流程时：** 简短提醒一次，确认后直接改，改完仍补上实际改动清单。

**用户时间压力：** 理解处境，不进行说教。可压缩评估和清单篇幅，但改动清单和"继续"关卡不能省；用户明确说"不用 review 直接改"时按用户说的办。

## 典型情景

### 情景1: 舒适区内任务

```
用户: 帮我加一个函数，把 JSON 文件读取并转成 dict

AI:
  评估: 读取JSON→解析dict | 难度* | 舒适区
  方案: 1. json.load()  2. 加错误处理  3. 独立函数
  改动清单（1 个文件）:
    utils/json_io.py（修改）
      - 改哪里: import 之后新增 read_json()
      - 为什么改: 接收路径并返回 dict（对应方案 1 + 2）
  > Review 完回「继续」，我再开始改文件。

用户: 继续
AI: (新增 utils/json_io.py::read_json，约 12 行)
  实际改动: 仅 utils/json_io.py，与清单一致
  验证: 跑了 tests/test_json_io.py，3 个用例通过
```

### 情景2: 安全敏感任务

```
用户: 帮我加一个登录接口，验证用户名和密码

AI: (先扫描项目: Flask + SQLAlchemy，已有 User 模型)

  评估: 接收用户名密码→查库验证→返回结果 | 难度** | 有挑战 | !!高风险!!
  项目: 已有 User 模型可复用，需确认密码是否已哈希存储

  方案: 1. ORM查询(防注入)  2. check_password_hash  3. Flask session/JWT

  !! 安全提醒: 不拼接SQL、密码必须哈希、统一返回"用户名或密码错误"、做速率限制

  改动清单（3 个文件）:
    routes/auth.py（修改）     - 改哪里: 新增 login() 视图       - 为什么改: 接口入口 + ORM 查询
    auth/security.py（修改）   - 改哪里: verify_password()        - 为什么改: 哈希校验，不用 == 比较
    tests/test_auth.py（修改） - 改哪里: 错误密码、速率限制用例    - 为什么改: 锁住安全行为
  > Review 完回「继续」，我再开始改文件。
```

### 情景3: 审查 AI 的改动

```
用户: 刚才 AI 改的这 3 个文件合理吗？

AI: (审查模式，不动文件)
  结论: 基本合理，一处风险
  - routes/auth.py:42 密码用 == 比较 → 改用 check_password_hash（3 行修正）
  - auth/security.py:18 日志打印了整个请求体 → 密码字段要脱敏
  - tests/test_auth.py 缺少错误密码的确定性用例 → 补一个

  需要修的话，我先出一份改动清单，等你说「继续」再动手。
```

## 常见错误（AI 侧）

| 错误 | 正确做法 |
|------|----------|
| 清单写成"改一下相关模块" | 写清文件、位置、理由 |
| 弹选择或问"要不要开始改" | 一句话等"继续" |
| 没等"继续"就"先准备一下"并改文件 | 授权前只交付清单 |
| 用户说"继续"后夹带清单外改动 | 只做清单内的 |
| 改完只说"已完成" | 报实际改动 + 验证结果 |
| 评估阶段输出完整实现 | 评估只给方案和 <=10 行片段 |
| 审查 AI 改动时重写整个函数 | 列问题 + <=3 行修正建议 |
| 简单任务省掉清单 | 评估可精简，清单 + "继续"关卡不能省 |
