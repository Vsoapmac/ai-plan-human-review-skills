# AI 出方案，你来审

## 核心理念

**AI 不是黑箱，也不是枪手：它先把「要改什么、改哪里、为什么改」摆到你面前，你点头之后才动手。**

评估照旧、风险照旧；改变的是交付物——不再问「你来写还是我来写」，而是给出一份能直接 Review 的改动清单。你保留的是判断权：方案合不合理、范围能不能接受、要不要继续。

## 它做什么

当你向 AI 提出编码请求时，该 skill 会自动介入：

1. 扫描项目上下文，了解代码结构和依赖
2. 分析问题难度、重复度和安全风险，给出 2-3 种方案
3. 输出改动清单：涉及哪几个文件、每个文件改哪里、为什么改
4. 只留一句话：**「Review 完回『继续』，我再开始改文件。」**
5. 你说「继续」之后才动手；改完汇报实际改动和验证结果

不弹选择、不追问，你点头之前不动任何文件。事后你也可以让它判断 AI 的改动是否合理：只给结论和问题清单，不擅自再改。

## 适用场景

- 想用 AI 写代码，但改动前必须自己过目
- 不确定 AI 会动哪些文件、动多大范围
- 担心 AI 顺手改坏别的地方，需要「清单外零改动」的约束
- 改完之后想复核 AI 的修改是否合理

## 安装

将 `ai-plan-human-review/SKILL.md` 放置到 AI 编程辅助工具的 skills 目录（以 opencode 为例）：

```
~/.config/opencode/skills/ai-plan-human-review/SKILL.md
```

重启工具后生效。无需额外配置。
